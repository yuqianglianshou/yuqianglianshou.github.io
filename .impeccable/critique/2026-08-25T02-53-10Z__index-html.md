## Design Specificity Verdict

**有作者气质，但只停留在封面和关于页，内容层仍较模板化。** 背景照片、头像、“喜欢你 / 那双眼动人”和关于页短句让首屏具有私人站辨识度；进入文章流后，左侧封面、白色文章卡、旧式归档和标签长列表都可被另一位博主直接复用。最大机会不是增加装饰，而是让作者气质延续到排版、索引结构、标签语义和阅读收束。

**Deterministic scan：** 对 16 个代表性模板、include、页面与文章文件执行一次 detector，exit 0，结果 `[]`。这是规则未命中，不代表没有问题。静态构建 DOM 仍确认：所有代表页面都没有 `<main>`；首页滚动提示是 click-only `<div>`；首页文章列表初始隐藏且依赖 JS；归档页约 141 个链接，标签页约 149 个链接。浏览器后端为空，无法做真实桌面/移动截图、computed style、console detector 或用户可见 overlay。

## Overall Impression

第一眼有温度、有个人记忆点；第二步进入内容时，体验突然变成高密度的旧式 Jekyll 索引。最大的机会是建立一套真正面向“阅读”的系统：让首屏、文章列表、长文、归档、标签和关于页共享同一套层级、节奏与颜色语义。

## What's Working

1. 全屏背景、头像和短文案建立了清晰的私人站开场，不像普通技术博客。
2. 文章已有 `article/header/section`、日期、图片 alt、代码块和 reduced-motion 基础，内容资产本身较完整。
3. 关于页的信息分组和短句节奏比其他页面成熟，可作为后续视觉语气的参考，而不是推倒重来。

## Priority Issues

### [P1] 首页核心内容依赖 JS 才可发现

- **What：** `.main-post-list` 初始带 `hidden`，用户需理解并点击“博客主页”或非原生的“查看博客”才能看到文章。
- **Why it matters：** 首次访问者可能把首屏当成只有个人名片的站点；脚本失败时文章入口消失；两个文案触发同一结果也增加理解成本。
- **Fix：** 文章索引应默认可访问，封面作为视觉增强；保留一个明确主动作，原生链接/按钮承担交互并显示当前状态。
- **Suggested command：** `$impeccable clarify` + `$impeccable layout`

### [P1] 无障碍基础存在硬伤

- **What：** 全局 `*:focus { outline: none; }`，只有部分导航补回焦点；`.scroll-indicator` 是 click-only `<div>`；代表页面无 `<main>` 和 skip link；元数据、页脚、关于页 kicker 等存在低对比度；移动导航触控目标偏小。
- **Why it matters：** 键盘、屏幕阅读器、低视力和移动用户无法可靠完成“找到并阅读文章”这一主任务。
- **Fix：** 统一 `:focus-visible`；动作改用原生 `a/button`；补 `<main>`、跳至正文和活动导航；正文小字达到 WCAG AA；触控目标至少 44×44px。
- **Suggested command：** `$impeccable audit`

### [P1] 长文阅读缺少方向感

- **What：** 最新长文包含十余个二级章节，无目录、当前章节或返回顶部；文章开头先出现强调型 `h3`，再进入 `h2`；正文基础字号 14px，内容容器最大 920px，行长偏宽。
- **Why it matters：** 技术长文在中段形成明显阅读低谷，用户难预估长度、定位章节或中断后恢复。
- **Fix：** 正文控制在约 680–760px，桌面正文 17px/1.8 左右、移动端不低于 16px；修正标题结构；为长文生成可折叠目录、当前章节提示和返回顶部。
- **Suggested command：** `$impeccable typeset` + `$impeccable layout`

### [P2] 索引页信息密度失控

- **What：** 首页每页 20 篇、每篇约 250 字摘要，并重复日期/标签/阅读全文；归档和标签页一次暴露上百链接，标签页标题为空。
- **Why it matters：** 用户面对的是滚动成本而不是选择帮助，最新、重要、相关三种价值没有层级。
- **Fix：** 首页保留 8–10 篇、摘要缩至 80–120 字；增加“最新文章”标题；归档按年份紧凑分组并提供年份导航；标签页先显示标签与数量，再呈选中标签文章。
- **Suggested command：** `$impeccable distill`

### [P2] 视觉系统和对齐规则没有收敛

- **What：** 源 SCSS 含 106 个独立颜色字面量；正文链接蓝、文章卡绿、关于页橙、全局 h3 浅蓝、旧组件红色并存。首页内容区 `width:70%; margin-left:30%`，文章页则 `78%/22%`；段落全局左 padding 20px，标题、列表、图片和代码块缺少共同文本轴。
- **Why it matters：** 页面像不同年份的局部优化叠加；颜色无法表达稳定语义，对齐漂移削弱专业感。
- **Fix：** 建立中性底色、正文色、次级色、一个品牌主色、一个作者性强调色和状态色 token；统一 8px 间距节奏、容器栅格、圆角和文本轴；让关于页风格被吸收到全站，而非保持孤岛。
- **Suggested command：** `$impeccable document` + `$impeccable colorize` + `$impeccable layout`

## Eight-Dimension Findings

### Visual hierarchy

1. 首页视觉峰值集中在头像和背景，真正目标“读文章”权重过低。
2. 展开后没有“最新文章”或栏目说明，第一张卡片突然成为页面起点。
3. 卡片内标题、摘要、日期、标签、阅读全文都获得接近权重；主阅读路径不够干净。
4. 标签页空 `h1`、年份/标签直接使用全局 `h3`，页面级与分组级层级不完整。

### Typography

1. 14px 基础字号不足以支撑中文长文和低视力阅读。
2. 预期的 `ff-tisa` 未实际加载，跨系统回退字体会改变字面、行高和密度。
3. 标题大量使用 `font-weight: lighter`，中文字体支持不稳定，可能呈现为默认字重。
4. 全局段落 `padding-left:20px` 不是排版缩进，造成正文、列表、图片和代码块左边界不一致。
5. 代码、表格、引用和 h3 各自有强背景/边框，争夺正文注意力。

### Spacing

1. 主页卡片内部空间尚可，但 20 张卡片连续出现导致页面节奏机械。
2. 全局段落、列表、表格使用不同的 margin 模型，没有统一垂直节奏。
3. 表格 `margin:50px auto`、代码块额外宽度和 padding 在移动端可能造成异常空白或横向滚动。
4. 页脚字号和间距过小，像遗留信息而非完成阅读后的明确收束。

### Alignment

1. 首页 30/70 与文章 22/78 的左右分栏不是同一栅格。
2. 宽屏下封面最大 320px，但首页正文仍从 30% 开始，可能形成无意义空带。
3. 段落、标题、列表、引用、图片、代码块没有共享文本轴。
4. 移动导航用 float 和固定 40px 高度容纳 6 项，存在换行、重叠和触控拥挤风险。

### Color system

1. 106 个颜色字面量说明色彩主要按局部页面选择，而不是按语义复用。
2. 链接 hover 从青蓝跳到纯蓝，卡片强调绿、关于页橙、全局 h3 蓝、旧按钮红，品牌重心不稳定。
3. 已计算的对比度中：`#9aa8b2`/白 2.44:1、`#8a97a1`/白 2.99:1、`#b3b3b3`/白 2.10:1、`#db7b46`/`#fff7ef` 2.86:1，均不适合普通小字号文本。
4. 配置 `cover_color: clear` 生成 `cover-clear`，而样式只定义 `cover-disabled`，背景文字对比可能随图片区域变化。

### Accessibility

1. 全局移除焦点轮廓，正文链接、标签和页脚图标没有可靠键盘焦点。
2. “查看博客”是可点击 `div`，无 button 语义、tabindex 或键盘事件。
3. 缺少 `<main>` 和跳至正文；桌面/移动两套导航让辅助技术需要重复遍历。
4. 页面标题结构包含侧栏头像 `h2`、站点 `h1`、内容 `h1`；标签页内容 `h1` 为空。
5. 6 个移动导航项文字小、padding 小，未达到建议的 44px 触控尺寸。
6. 已支持 `prefers-reduced-motion`、装饰图 alt 为空、内容图有描述性 alt，这些应保留。

### Information density

1. 首页 20×250 字摘要使“选一篇读”变成浏览长墙。
2. 归档约 141 个链接、标签页约 149 个链接，无搜索、年份跳转或渐进披露。
3. 首页六个一级入口超过单一决策点建议的 4–5 项，可将“小玩乐/小工具”归入“作品”或次级入口。
4. 长文十余章节无目录，用户需要靠记忆维持位置。

### Consistency

1. “所有文章/文章”“关于他/他”、中文正文与英文 `title` 文案不统一。
2. 首页、文章卡、关于卡片、归档和标签列表的圆角、边框、阴影和背景体系不同。
3. 当前导航没有 active/`aria-current`，同一路径在不同页面看起来没有状态差异。
4. hover、focus 和 touch 的反馈并不对等；头像翻转信息依赖 hover，触屏和键盘无法获得同等体验。

## Persona Red Flags

- **Jordan（首次访问者）：** 首屏更像个人名片，不确定“博客主页”和“查看博客”是否同一动作；标签页空标题，“关于他/他”含混，5 秒内难建立站点地图。
- **Sam（无障碍用户）：** 无 skip link、无 `<main>`、全局焦点被移除、click-only `div`；重复导航和多 H1/空 H1 增加屏幕阅读器成本。
- **Casey（移动分心用户）：** 40px 顶栏塞入 6 个入口、长摘要与标签长列表滚动过重；长文无目录或位置恢复，中断后很难继续。

## Minor Observations

- 首页 `body` 在脚本里先设透明，再等待 load 淡入；外部资源较慢时会延迟首屏可见性。
- 头像首屏图片使用 `loading="lazy"`，可能让最重要的视觉元素延迟出现。
- 外链在新窗口打开但没有视觉提示。
- `pre { overflow: scroll; }` 会始终保留滚动机制，桌面观感偏旧。
- 归档日期存在 `2026-05- 5` 一类空格不一致，降低扫描整齐度。

## Questions to Consider

1. 这个博客的第一任务是“认识作者”还是“尽快进入文章”？目前两者都存在，但封面压过了阅读。
2. “小玩乐”和“小工具”是一级栏目，还是更适合统一成为“作品”？
3. 关于页已经形成暖色、克制、直接的表达，是否应该成为全站内容层的视觉基准？
